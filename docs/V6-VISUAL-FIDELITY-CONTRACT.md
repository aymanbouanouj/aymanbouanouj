## Styling contract

- Baseline dark navy background: `#0a0d18`, softly brighter panels: `#151a2b`.
- Violet accent: `#b46aff`. Accent glow is restrained. Primary content: `#f6f7ff`, supporting metadata: `#bdc2d5`.
- Panel stroke: `#42415d`; parent panel radius ≈ 18 and interior card radius ≈ 14 on a 1000px SVG grid.
- Maintain identical content/card gutters across the renderer and project card rasterizer.
- Use official, locally vendored brand icons and public project screenshots, **never** arbitrary icon initials, stock screenshots or counterfeit Github statuses.
- Keep technical stack as 6 × 2 tiles; build tools as seven compact tiles; projects as three independent 245 × 218-reference-proportion cards; pins as two rows of independent clickable cards.

## Real interactions

Images inside `<img>` are passive. A hero *visual* cannot contain independently working CTA buttons; real Portfolio, LinkedIn and Projects buttons must be individual `<a href><img ...></a>` elements in README. Project and pinned cards similarly link to distinct actual public repositories.

No self-referential GitHub button is displayed. Email is omitted until a public address is verified.

## Dynamic data, truth and privacy

- Four counters **cannot be copied from the mockup**. Actual annual contributions/streak/external confirmed merges/public repositories are derived from existing validated snapshots; current-streak semantics and recent-PR sample scope must stay explicit.
- The native GitHub contribution graph is authoritative; the PNG/SVG heatmap is a dated snapshot.
- Technical tools can be owner-declared but verified programming languages and frameworks must have GitHub Linguist/dependency-manifest evidence.
- Private code and names never appear; only authorized, aggregated private-language code bytes may be published.
- A `profile-cover.png` uploaded to an allowed project path triggers card regeneration at the next successful scheduler run; otherwise a full-size **image pending** placeholder remains.
- Open PRs and issues must not be shown as merged; no invented stars, forks or demo links.
- GitHub page header, account sidebar, native pinned sections, and responsive page container cannot be altered from README.

## Release acceptance tests

1. Offline unit/regression, Gitleaks, CodeQL Python and Actions all **pass on the last PR SHA**, not a previous commit.
2. Every reference-linked dynamic asset exists on `profile-live` before review.
3. V6 project card PNGs have identical aspect ratio and full title/description/technology/actual-source footer; no blank image gaps.
4. Visual review of GitHub **Overview** and **README file Preview** at 780px, 600px and 375px content widths, in both GitHub themes; compare each of nine bands to the reference.
5. Validate all anchor destinations, image cache behavior, refresh cadence, GitHub privacy and repository-permissions defaults.
6. Merge only after an acceptable visual comparison. The V5 published page stays unchanged until merge.

**Known rollout limitation:** latest fully styled project PNGs are generated by the branch's scheduled workflow, which is not active on protected `main` while this is a draft PR. Existing `profile-live` assets may be seeded previews. The final deployment must verify regenerated PNG metadata before declaring completion.
